# Preview deployment runbook

ConvoWeave publishes the processing backend as a versioned container artifact and keeps runtime identity/provider secrets outside the image.

## Container publishing

After `Backend CI` succeeds for a trusted `main` commit, `.github/workflows/container-publish.yml` builds and publishes:

- `ghcr.io/drewc611/convoweave-backend:main`
- `ghcr.io/drewc611/convoweave-backend:sha-<12-character-commit>`

The SHA tag is the immutable deployment/rollback reference. The `main` tag is a moving convenience pointer.

The published image includes OCI source/revision metadata, provenance, and an SBOM generated by the Docker build action. No OpenAI key, OIDC secret, Apple/Google credential, recording, transcript, or meeting data is baked into the image.

## Preview runtime

Use `deploy/docker-compose.preview.yml` as the portable reference runtime. Copy `deploy/.env.preview.example` to `deploy/.env.preview` on the host and replace placeholders only on that host or through the hosting platform's secret manager.

The Compose deployment mounts a durable `convoweave-preview-data` volume at `/data/convoweave` and uses the backend's public liveness healthcheck.

## Required runtime inputs

A real AI + identity preview requires values supplied outside Git:

- `PUBLIC_BASE_URL`
- OIDC issuer, API audience, and JWKS URL
- OpenAI API key or another future processing-provider credential
- the backend image tag to deploy

The OpenAI credential is backend-only. The mobile app receives only the ConvoWeave API URL and a user access token supplied by the configured identity provider.

## Deployment

From the `deploy` directory on the preview host:

```bash
cp .env.preview.example .env.preview
# populate runtime values using the host/platform secret mechanism
docker compose -f docker-compose.preview.yml pull
docker compose -f docker-compose.preview.yml up -d
```

Then validate public service state:

```bash
CONVOWEAVE_PREVIEW_URL=https://preview-api.example.com \
CONVOWEAVE_EXPECT_PROVIDER=openai \
CONVOWEAVE_EXPECT_AUTH=oidc \
CONVOWEAVE_EXPECT_STORAGE=filesystem \
node smoke-preview.mjs
```

The smoke command prints service metadata only. It does not print or require provider credentials, bearer tokens, recordings, or transcripts.

## Rollback

Never roll back by guessing what `main` previously pointed to. Set `CONVOWEAVE_BACKEND_IMAGE` to the last validated immutable SHA tag, then pull/recreate the service:

```bash
export CONVOWEAVE_BACKEND_IMAGE=ghcr.io/drewc611/convoweave-backend:sha-0123456789ab
docker compose -f docker-compose.preview.yml pull
docker compose -f docker-compose.preview.yml up -d
```

Session persistence remains on the mounted volume and is independent of the image tag. Do not roll back across an incompatible persisted-store schema without an explicit migration/rollback plan.

## Exposure rules

Do not expose a `development-token` preview backend to the public internet. Internet-facing preview should use OIDC and HTTPS through the hosting platform/reverse proxy.

Use `delete-after-processing` audio retention unless a controlled, non-sensitive preview investigation explicitly requires `retain-preview`.

## External account boundary

This repository can build and publish the image, but an actual internet preview still needs a runtime host, DNS/TLS endpoint, identity-provider configuration, and provider API credential. Those are deployment-account actions and are intentionally not stored in the repository.
